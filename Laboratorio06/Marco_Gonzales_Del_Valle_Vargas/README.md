# Laboratorio 06 — Marco Antonio Gonzales del Valle Vargas

API REST **CRUD de productos persistida en MySQL**, según la Guía de Laboratorio 06
(Manejo de datos con Spring Boot, JPA, Hibernate y operaciones CRUD).

La API de la semana 5 guardaba los productos en memoria. Aquí se reemplaza ese
almacenamiento por una capa de persistencia real: `Producto` pasa a ser una entidad JPA,
aparece `ProductoRepository` y el `ProductoService` delega el guardado en el repositorio.
El `ProductoController` queda prácticamente igual, que es justamente lo que demuestra el
desacoplamiento entre la capa web y la capa de datos.

## Tecnologías

- Java 25
- Spring Boot 4.1.1 (Spring Web, Spring Data JPA, Starter Test, Starter Data JPA Test)
- Hibernate como implementación ORM
- MySQL 8 (driver `com.mysql:mysql-connector-j`)
- Maven Wrapper (`mvnw` / `mvnw.cmd`)
- H2 en memoria, **solo con alcance `test`**, para poder ejecutar `@DataJpaTest` sin MySQL

## Estructura

```
src/main/java/com/utp/productosapi
├── ProductosApiApplication.java
├── controller
│   └── ProductoController.java     → endpoints /api/productos
├── service
│   └── ProductoService.java        → reglas de negocio + @Transactional
├── repository
│   └── ProductoRepository.java     → extends JpaRepository<Producto, Long>
└── model
    └── Producto.java               → @Entity @Table(name = "productos")

src/main/resources/application.properties   → conexión MySQL y configuración JPA
src/test/java/com/utp/productosapi/repository/ProductoRepositoryTest.java
sql/01_crear_base_datos.sql                 → CREATE DATABASE productos_db
sql/02_verificar_tabla.sql                  → SHOW TABLES / DESCRIBE / SELECT
postman/Laboratorio06_Productos.postman_collection.json
```

Flujo completo: petición HTTP → Controller → Service → Repository → JPA/Hibernate → JDBC → MySQL.

## Cómo ejecutarlo

**1. Crear la base de datos** (MySQL Workbench o consola):

```sql
CREATE DATABASE productos_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

La tabla `productos` no se crea a mano: Hibernate la genera desde la entidad porque
`spring.jpa.hibernate.ddl-auto=update`.

**2. Poner la contraseña de MySQL** en `src/main/resources/application.properties`
(reemplazar `TU_PASSWORD`).

**3. Levantar la aplicación:**

```bash
./mvnw spring-boot:run      # Windows: mvnw.cmd spring-boot:run
```

**4. Verificar la tabla:**

```sql
USE productos_db;
SHOW TABLES;
DESCRIBE productos;
SELECT * FROM productos;
```

## Endpoints

| Método | URL | Respuesta |
|--------|-----|-----------|
| GET | `/api/productos` | 200 + lista |
| GET | `/api/productos/{id}` | 200 / 404 |
| POST | `/api/productos` | 201 + producto con `id` generado por MySQL |
| PUT | `/api/productos/{id}` | 200 / 404 |
| PATCH | `/api/productos/{id}/precio?valor=4200` | 200 / 404 |
| DELETE | `/api/productos/{id}` | 204 / 404 |

Ejemplo de creación:

```bash
curl -X POST http://localhost:8080/api/productos \
  -H "Content-Type: application/json" \
  -d '{"nombre":"Laptop Lenovo","precio":3500,"stock":10}'
```

La colección de Postman con las seis operaciones está en
[postman/Laboratorio06_Productos.postman_collection.json](postman/Laboratorio06_Productos.postman_collection.json).

## Reto práctico (sección 21)

Se agregó el campo `categoria` a la entidad:

```java
@Column(nullable = false, length = 80)
private String categoria;
```

Al reiniciar la aplicación, Hibernate ejecuta un `ALTER TABLE` y la columna aparece en
`DESCRIBE productos`. Como la columna es `NOT NULL` y los ejemplos de Postman de la guía
no envían `categoria`, el `ProductoService` asigna `"General"` cuando el cliente la omite;
así los ejemplos de la guía siguen funcionando sin que falle el `INSERT`.

No se agregaron consultas JPQL: eso corresponde a la semana 7.

## SQL generado por Hibernate (sección 17)

Con `spring.jpa.show-sql=true` se observan en consola sentencias como estas:

```sql
create table productos (id bigint generated by default as identity, categoria varchar(80) not null,
       nombre varchar(120) not null, precio float(53) not null, stock integer not null, primary key (id))
insert into productos (categoria, nombre, precio, stock, id) values (?, ?, ?, ?, default)
select p1_0.id, p1_0.categoria, p1_0.nombre, p1_0.precio, p1_0.stock from productos p1_0
select p1_0.id, p1_0.categoria, p1_0.nombre, p1_0.precio, p1_0.stock from productos p1_0 where p1_0.id=?
update productos set categoria=?, nombre=?, precio=?, stock=? where id=?
delete from productos where id=?
select count(*) from productos p1_0 where p1_0.id=?
```

El `count(*)` corresponde a `existsById()` dentro de `eliminar()`, y el `insert` con
`id default` confirma que el identificador lo genera el motor por el
`GenerationType.IDENTITY` (`AUTO_INCREMENT` en MySQL).
